# NEXUS Web

Private working slice for the NEXUS event experience. This increment contains a touch-first attract/hub shell, one JLTV configurator using the supplied model, one guided hotspot, a 30-product demonstration Explorer catalog, autogenerated follow-up content, and a durable local pending-request queue. Catalog copy and media are filler placeholders and are not approved product marketing.

## Run

```bash
npm ci
npm run dev
```

The proprietary runtime model is intentionally excluded from Git. Place the optimized derivative at `public/assets/jltv-runtime.glb`. The preserved original must remain outside the repository.

## Verify

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e:quality
npm run build
npm run preview
```

## Status boundaries

- Email transport is deliberately unconfigured. Requests persist in IndexedDB as `pending-not-configured`; the UI never reports them sent or delivered.
- Usage analytics are local and structurally exclude visitor name/email.
- The service worker caches the bounded shell and runtime model after provisioning. Browser storage can still be evicted; device-reboot acceptance is deferred until representative hardware is available.
- `Addon 1` is the model's supplied attachment and is not labeled MXR. `roof-system-anchor` is an abstract replacement point, not a verified physical mount.
- The public Storybook was inspected directly and the approved primary token values are mapped locally (`base-white`, `purple-950`, `purple-800`, `ultraviolet-500`, `ultraviolet-800`). Original private “Avenir Next for Leidos” binaries from the MHC handoff are integrated into the private build and excluded from Git; see `docs/PRIVATE-FONT-PROVENANCE.md`. Public redistribution rights are not assumed. The private component package remains unavailable, so local component adapters are still used.
- Design hierarchy: the user's supplied screen references and NEXUS Figma govern product-specific visual direction; the approved Leidos system governs colors, fonts, and reusable components; `NEXUS-POC` is behavior-only context. The November corrective references were inspected as pixels and are recorded in `docs/design-provenance.md`.

## Local configuration boundaries

Validated active/previous event configuration bundles and operator preferences persist in IndexedDB. Activation checks the schema and SHA-256 integrity; a corrupt active bundle falls back to the previous verified bundle, then the packaged seed. Rollback is explicit. This is resilient local event state, not a secure CMS or publication authority.

The future trusted CMS and event-publication ports are declared in `src/contracts/cms.ts`. Role enforcement, accounts, draft publication, signed distribution, and trusted authorization remain backend work. The operator menu is intentionally not a security boundary.

Explorer catalog delivery now has a vendor-neutral, schema-validated read adapter with validated IndexedDB fallback and packaged demonstration content. Configure `VITE_NEXUS_CMS_CATALOG_URL` with a normalized public-read JSON publication; see [docs/EXPLORER-CMS-CONTRACT.md](docs/EXPLORER-CMS-CONTRACT.md). No Drupal endpoint, credentials, or production content mapping is assumed.

Visitor requests use a separate durable outbox. Invalid records are quarantined, rapid duplicates are suppressed, and the current transport is explicitly `not-configured`; it cannot mark a request sent.
- Operator controls are a convenience surface, not an access-control boundary.
